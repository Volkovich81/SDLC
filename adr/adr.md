\# Выбор технологического стека для разработки CurrencyForecast



\## Контекст и постановка задачи

В рамках лабораторных работ разрабатывается веб-приложение для прогнозирования курсов валют (CurrencyForecast). Согласно учебному заданию, основным языком разработки выбран Java. Необходимо спроектировать архитектуру, которая объединит веб-интерфейс, серверную логику и модуль машинного обучения в единую экосистему.



\## Драйверы решения

\* \*\*Требование дисциплины:\*\* весь бэкенд должен быть написан на Java.

\* \*\*Производительность:\*\* система должна быстро обрабатывать запросы к базе данных и внешним API (время отклика < 2 сек).

\* \*\*Интеграция ML:\*\* необходимость внедрить алгоритмы машинного обучения без развертывания дополнительных Python-серверов.



\## Рассмотренные варианты

\* \*\*Вариант 1:\*\* Java + Spring Boot + Библиотека Smile (для ML).

\* \*\*Вариант 2:\*\* Java + Spring Boot + Вызов внешнего Python-микросервиса по API (где крутится scikit-learn).

\* \*\*Вариант 3:\*\* Node.js + TensorFlow.js (отклонен, так как нарушает требование использования Java).



\## Итог решения

Выбранный вариант: \*\*«Вариант 1: Java + Spring Boot + Библиотека Smile»\*\*, потому что он позволяет сохранить единый язык программирования (Java) для всей серверной части, что упрощает сборку, развертывание и поддержку проекта (монолитная архитектура без лишних сетевых задержек).



\### Последствия

\* \*\*Хорошо, потому что\*\* мы не тратим время на написание и поддержку двух разных бэкендов (Java и Python). Разработчик может отлаживать весь код в одной среде (IntelliJ IDEA).

\* \*\*Плохо, потому что\*\* экосистема ML-библиотек на Java (Smile) менее обширна, чем на Python. Некоторые сложные нейросети реализовать будет труднее.

\* \*\*Нейтрально:\*\* Для хранения данных выбрана PostgreSQL как надежная реляционная СУБД, хорошо интегрируемая со Spring Boot.



\### Подтверждение

Использование Java и Spring Boot подтверждается структурой папок `src/main/java`. Наличие зависимостей `smile-core` и `spring-boot-starter-web` в файле `pom.xml` (или `build.gradle`) будет являться автоматическим подтверждением соблюдения данного архитектурного решения при code review.



\## Плюсы и минусы вариантов



\### Вариант 1: Java + Spring Boot + Smile

\* Хорошо, потому что весь проект пишется на одном языке (Java).

\* Хорошо, потому что Spring Boot имеет встроенный веб-сервер Tomcat, что упрощает запуск.

\* Плохо, потому что ML-модели на Java могут уступать по скорости обучения Python-аналогам.



\### Вариант 2: Java + Python (Микросервис)

\* Хорошо, потому что можно использовать самые передовые ML-библиотеки Python (pandas, scikit-learn).

\* Плохо, потому что требуется настраивать сетевое взаимодействие (REST/gRPC) между Java и Python.

\* Плохо, потому что усложняется развертывание (нужно поднимать два контейнера вместо одного).
