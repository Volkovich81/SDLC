## 1. Введение

### 1.1 Назначение документа
Данный документ (SDD) описывает архитектуру, дизайн и внутреннее устройство веб-приложения «CurrencyForecast». Он предназначен для команды разработчиков (Frontend и Backend), а также для архитекторов, которым предстоит реализовывать данный проект. Документ служит руководством к действию на этапе написания кода.

### 1.2 Область применения
Проектируемая система — веб-приложение «CurrencyForecast» версии 1.0. Основное назначение: предоставление пользователям актуальных и исторических курсов валют с возможностью визуализации данных и прогнозирования (ML) на 7 дней вперед. 
Входит в область проектирования: клиентская часть (UI), серверная часть (API), модуль машинного обучения и база данных.
НЕ входит: реальные финансовые транзакции, системы аутентификации пользователей (личные кабинеты) и мобильные приложения.

## 2. Обзор дизайна

### 2.1 Задачи стейкхолдеров
* Пользователи: получение быстрого и точного прогноза курса валют.
* Разработчики: понятная модульная архитектура для параллельной разработки.
* Операторы (DevOps): легкое развертывание приложения.

### 2.2 Выбранные точки зрения
Для описания архитектуры выбраны следующие точки зрения:
* Контекст (Context): для определения границ системы и внешних API.
* Композиция (Composition): для разбиения системы на модули (Frontend, Backend, ML).
* Информация (Information): для описания схемы базы данных.

## 3. Проектные представления

ID: [001]-Context View
Title: Контекстная диаграмма системы
Viewpoint: Context
Representation: Пользователь взаимодействует с Web-интерфейсом (Frontend). Frontend отправляет HTTP-запросы к Backend (Spring Boot). Backend запрашивает данные у внешнего API Национального Банка РБ и обращается к ML-модулю для получения прогноза.

ID: [002]-Composition View
Title: Логическая декомпозиция на модули
Viewpoint: Composition
Representation: Система состоит из трех ключевых компонентов: WebClient (HTML/JS), BackendService (Java/Spring Boot), MLService (Java/Smile).

ID: [003]-Information View
Title: Модель данных
Viewpoint: Information
Representation: Используется реляционная СУБД PostgreSQL. Основные сущности: Currency (id, code, name) и RateHistory (id, currency_id, date, rate_value).

## 4. Решения
Все ключевые архитектурные решения вынесены в отдельные документы ADR. Краткая сводка:
* ADR-001: Выбор Spring Boot в качестве основного фреймворка.
* ADR-002: Выбор библиотеки Smile для реализации ML-прогноза на Java.
